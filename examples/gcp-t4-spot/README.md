# Google Cloud (T4 Spot VM)

vLLM serving Qwen3-0.6B (fp16) on one T4 Spot VM in `europe-west4`, deleted by Compute Engine after 2 hours. Replace `your-gcp-project-id` (also in `service_account`, an account you create first: see the docs page), run `gcloud auth application-default login`, export `CHAT_API_KEY` (a random key, for example `openssl rand -hex 32`) and run `amicu apply`. The endpoint is HTTPS with a self-signed certificate that `apply` writes next to state and whose fingerprint it prints (clients pin it), the secrets live in Secret Manager and are deleted by `amicu destroy`, and the firewall rule allows only your public IP unless you set `allowed_source_cidrs`. `idle_shutdown = "30m"` powers the VM off after half an hour without a request (remove it to serve until `max_run_duration`); the VM is then only stopped, not deleted: its boot disk keeps billing and `max_run_duration` likely no longer applies until the next `amicu apply` or `amicu destroy` deletes it. See https://amicu.dev/docs/providers/gcp.
