# Releasing amicu

Releases are automated: [release-plz](https://release-plz.dev) versions and tags, [dist](https://github.com/axodotdev/cargo-dist) (cargo-dist) builds and publishes. The whole workspace shares one version (`[workspace.package].version`), released under one `vX.Y.Z` tag. Only the `amicu` CLI (package `amicu-cli`) is distributed; `amicu-server` has `publish = false` and `dist = false`. Nothing is published to crates.io.

## How a release happens

1. PRs are squash-merged to `main` with a Conventional Commit title (`type(scope)!: summary`, enforced by the `pr-title` check). `feat` bumps the minor, `fix` / `perf` / `refactor` the patch; `!` marks a breaking change (while 0.x, minor).
2. On every push to `main`, the `release-plz` workflow opens or updates a release PR that bumps the workspace version, `Cargo.lock` and `CHANGELOG.md`.
3. Merge that PR; the `release` job (`release_always = false`) sees that the pushed commit comes from a release-plz PR and only then pushes the tag `vX.Y.Z` (using `RELEASE_TOKEN`, so the tag triggers other workflows). Pushes of ordinary commits to main never tag. `git_only = true` makes release-plz take the current version from git tags rather than crates.io.
4. The tag triggers `release.yml` (generated by dist): it builds `aarch64-apple-darwin`, `x86_64-apple-darwin`, `x86_64-unknown-linux-musl` and `aarch64-unknown-linux-musl`, creates the GitHub Release with archives, checksums, attestations and `amicu-cli-installer.sh`, and pushes the Homebrew formula `amicu` to `andypalmi/homebrew-tap`.

release-plz does not create GitHub Releases (`git_release_enable = false`); dist does. v0.1.0 is tagged by hand (`git tag v0.1.0 && git push origin v0.1.0`); release-plz takes over afterwards.

## Secrets (repository Actions secrets)

- `RELEASE_TOKEN`: fine-grained PAT (or GitHub App token) on `andypalmi/amicu` with Contents: read/write and Pull requests: read/write. A PAT/App token is required because tags and PRs created with `GITHUB_TOKEN` do not trigger other workflows.
- `HOMEBREW_TAP_TOKEN`: fine-grained PAT with Contents: read/write on `andypalmi/homebrew-tap`.

## One-time owner setup

1. Create the empty public repo `andypalmi/homebrew-tap`.
2. Add both secrets above.
3. Repo settings: allow squash merging, set its default commit message to "Pull request title"; allow GitHub Actions to create pull requests if using `GITHUB_TOKEN` fallbacks.
4. Make the `pr-title` check (and CI) required in the `main` ruleset.

## Dry runs

- `dist plan` lists the artifacts a release would produce (no build). `dist build --artifacts=local` builds for the host target.
- `dist generate --check` verifies `.github/workflows/release.yml` matches `dist-workspace.toml`; CI runs it. After changing `dist-workspace.toml` or upgrading dist, run `dist generate` and commit the result. Do not edit `release.yml` by hand.
- `release-plz update` (local, no token) shows the version bump and changelog the release PR would contain; revert the working tree afterwards.
- Pre-release: push a tag such as `v0.1.1-rc.1` to exercise the dist workflow; dist marks it as a pre-release.

## Actions pinning

Third-party actions are pinned to commit SHAs with a version comment. Actions used by `release.yml` are pinned through `[dist.github-action-commits]` in `dist-workspace.toml`.
