## Use this provider

```hcl
resource "hardware_profile" "ovh_gpu" {
  provider = "ovhcloud"
  region   = "GRA"
  accelerator {
    kind   = "gpu"
    model  = "l40s"
    count  = 1
    memory = "48GiB"
  }
  memory = "128GiB"
}
```

Running `amicu apply` against this profile fails before anything starts. To check it today, run `amicu validate` and `amicu plan`.

## Overview

OVHcloud is a French sovereign-cloud provider. The adapter drives the Public Cloud API to create, inspect, and delete single-GPU instances in a Public Cloud project. OVHcloud has no public spot market, so the catalog is on-demand only.

By default the adapter admits only EU data centers and rejects any other region before a backend call. Widening to other jurisdictions is an explicit choice in code; it is not exposed in HCL. The default set excludes the UK data center.

## Setup and credentials

The adapter authenticates with an OVHcloud API key. `apply` does not run this provider yet, so there is nothing to configure today. Credentials will be secret references only; never write a token into HCL (see [Secrets](/docs/security/secrets)).

## Configuration reference

| Argument | Type | Default | Required | Notes |
|---|---|---|---|---|
| `provider` | string | none | yes | `"ovhcloud"`. |
| `region` | string | none | no | One of the region codes below. Used for residency checks and cost estimates. |
| `accelerator.kind` | string | none | yes (with `accelerator`) | `gpu`. |
| `accelerator.model` | string | none | yes (with `accelerator`) | A GPU id from the table below, or any name that resolves to it (see [GPU names](/docs/configuration/hardware-profile#gpu-names)). |
| `accelerator.count` | number | none | yes (with `accelerator`) | Number of accelerators. |
| `accelerator.memory` | size | none | yes (with `accelerator`) | VRAM, for the fit check. |
| `memory` | size | none | yes | Host RAM. |
| `price.per_hour` | money block | none | no | Your own price, for cost planning. |

These are the generic [`hardware_profile`](/docs/configuration/hardware-profile) fields. There are no ovhcloud-specific arguments.

## Limits

- Not wired into `apply`.
- Single-GPU offerings only in the catalog.
- Prices in the catalog are illustrative values, not live quotes. amicu does not sync live capacity or pricing yet, so cost estimates are indicative.

## Troubleshooting

<Accordions>
  <Accordion title="apply says the provider is not supported">
  Expected. The error reads `provider "ovhcloud" is not supported by apply yet`. `apply` deploys to this machine, Modal and RunPod only. Provision the machine yourself, install the runtime there, and run amicu on it with the [`on_prem`](/docs/providers/local) provider. The endpoint then binds to loopback on that host.
  </Accordion>
  <Accordion title="validate or plan rejects the region">
  The region code must be one the catalog lists, and its jurisdiction must satisfy your [`data_class`](/docs/configuration/data-class) residency constraint. An unknown code is not guessed at: the residency check fails closed. See [Residency](/docs/concepts/residency).
  </Accordion>
</Accordions>
