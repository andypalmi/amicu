Amicu is a command-line tool for deploying open-weight LLM inference. You describe models, hardware, and deployments in HCL (`amicu.hcl`). Amicu checks the configuration, shows a plan against recorded state, and applies it by running llama.cpp or vLLM for you.

```bash
amicu init       # scaffold amicu.hcl and .amicu/
amicu validate   # structural, reference, capacity, and policy checks
amicu plan       # what apply would do, diffed against state
amicu apply      # start, update, or stop deployments after approval
```

The workflow is the one Terraform users know: configuration is declarative, every change is a plan you can read first, and state records what was applied.

## What it does

- Runs a llama.cpp or vLLM server where you choose: on your machine as a launchd (macOS) or systemd (Linux) user service, or on a remote GPU provider with a pinned region (Modal is supported today; others are in preview). See [Providers](/docs/providers).
- Checks that the model fits the hardware before anything starts.
- Treats data residency and provider allowlists as resources that `validate` and `plan` enforce.
- Keeps credentials out of configuration, plans, state, and command lines. See [Secrets](/docs/security/secrets).
- Verifies after every deploy that the endpoint rejects anonymous requests (loopback endpoints without an `api_key` skip this check). See [Endpoint auth](/docs/security/endpoint-auth).

## What it is not

- Not a hosted service. The CLI runs on your machine and talks only to the providers you deploy to. See [Telemetry and network](/docs/security/telemetry).
- Not a model registry or a gateway. It starts the runtime's own OpenAI-compatible server; clients call that server directly.
- Not a Kubernetes operator. There is no Helm or cluster delivery in the CLI today.
- Not stable. Expect breaking changes to the HCL schema and the CLI.

## Status

| Provider | Status |
|---|---|
| This machine (`local`, `local_apple`, `local_cpu`, `on_prem`) | Supported: `amicu apply` works |
| Remote GPU: Modal | Supported: `amicu apply` works |
| Hetzner, OVHcloud, Scaleway, RunPod, SSH hosts | Preview: adapter built, not tested live, not wired into `apply` |
| AWS, Azure, GCP, Nebius | Planned: region and pricing data only |

A deployment on a provider that `apply` does not support fails with an error. It never falls back to running locally. See [Providers](/docs/providers).
