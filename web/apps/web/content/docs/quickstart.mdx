## 1. Choose where to run

Two equal paths. Pick one; steps 2 and 3 are shared.

| | [Path A: on this machine](#path-a-on-this-machine) | [Path B: on a GPU provider](#path-b-on-a-gpu-provider) |
|---|---|---|
| Where | macOS or Linux, launchd or systemd user service | A remote GPU provider you have an account with |
| Runtime | llama.cpp or vLLM | llama.cpp or vLLM |
| Endpoint | Loopback, `api_key` optional | Public, `api_key` required |
| Status | Supported | Today `apply` supports Modal; Hetzner, OVHcloud, Scaleway, RunPod and SSH are in preview, and AWS, Azure, GCP and Nebius are planned |

See [Providers](/docs/providers) for every provider and its status.

## 2. Install

There are no published binaries yet. Both options need Rust 1.97 or newer.

Install the `amicu` binary into `~/.cargo/bin`:

```bash
cargo install --locked --git https://github.com/andypalmi/amicu amicu-cli
amicu --help
```

Or build from source:

```bash
git clone https://github.com/andypalmi/amicu.git
cd amicu
cargo build --release -p amicu-cli
export PATH="$PWD/target/release:$PATH"
amicu --help
```

Prebuilt binaries, a shell installer and Homebrew are coming with the first release.

## 3. Initialize a project

Create an empty directory and run `init` in it.

```bash
mkdir my-stack && cd my-stack
amicu init
```

`init` creates `amicu.hcl` (a starter config), `variables.amicu.hcl` (a placeholder), and `.amicu/` (project config and state). It never overwrites existing files.

## Path A: on this machine

Requirements:

- `llama-server` from llama.cpp on your `PATH` (on macOS, `brew install llama.cpp`). `apply` resolves it from `PATH` to an absolute path and fails with `llama-server not found on PATH; install with ...` if it is missing. `amicu doctor` reports whether it is found.
- A GGUF file for the model. Amicu does not download it; you do, once.

### The starter config

`amicu init` writes this `amicu.hcl`. It serves `Qwen/Qwen3-8B-GGUF` (`Qwen3-8B-Q4_K_M.gguf`, about 5 GB) with llama.cpp:

```hcl
resource "model" "qwen3_8b" {
  source {
    registry  = "hugging_face"
    reference = "Qwen/Qwen3-8B-GGUF"
  }
  architecture   = "qwen3"
  modalities     = ["text"]
  artifact {
    format       = "gguf"
    quantization = "q4_k_m"
  }
  context_length = 100000
  variant {
    quantization = "q4_k_m"
    file         = "Qwen3-8B-Q4_K_M.gguf"
    size         = "5027783488"
  }
}

resource "hardware_profile" "local_dev" {
  provider = "local_apple"
  accelerator {
    kind   = "apple_silicon"
    model  = "m4_pro"
    count  = 1
    memory = "48GiB"
  }
  memory = "48GiB"
}

resource "deployment" "qwen3_8b_local" {
  model    = model.qwen3_8b.id
  hardware = hardware_profile.local_dev.id
  runtime  = "llama_cpp"
  llama_cpp {
    context_length = 100000
    port           = 8000
    n_gpu_layers   = -1
  }
}
```

Edit `hardware_profile` to match your machine. On Linux without a GPU use `provider = "local_cpu"` with a `cpu {}` block instead; see [Hardware profile](/docs/configuration/hardware-profile). Lower `context_length` if memory is tight.

### Get the GGUF

The model resource id decides where the file goes: `models/<model id>/<variant.file>` relative to the project directory. Here that is `models/qwen3_8b/Qwen3-8B-Q4_K_M.gguf`. You can instead set `variant.file` to an absolute path.

```bash
mkdir -p models/qwen3_8b
curl -L -o models/qwen3_8b/Qwen3-8B-Q4_K_M.gguf \
  https://huggingface.co/Qwen/Qwen3-8B-GGUF/resolve/main/Qwen3-8B-Q4_K_M.gguf
```

For gated or private repos, add `-H "Authorization: Bearer $HF_TOKEN"`.

### Validate, plan, apply

```bash
amicu doctor
amicu validate
amicu plan
amicu apply
```

`plan` prints the exact `llama-server` command, including the absolute model path `<project dir>/models/qwen3_8b/Qwen3-8B-Q4_K_M.gguf`. `apply` shows the plan, asks for approval, installs a user service (launchd on macOS, systemd on Linux), starts it, and waits up to 15 minutes for `/health` to answer. If the service exits during startup, apply fails within seconds. On any failure it stops the service and the error gives the log location. See [This machine](/docs/providers/local).

### Send a request

The deployment has no `api_key`, so no header is needed; the endpoint is bound to `127.0.0.1`.

```bash
curl http://127.0.0.1:8000/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "Qwen/Qwen3-8B-GGUF", "messages": [{"role": "user", "content": "Hello"}]}'
```

If the request fails, check that the service is running and read its log: on macOS `~/Library/Logs/amicu/<label>.out.log` and `<label>.err.log`, on Linux `journalctl --user --unit=<label>`. The label is `io.amicu.llama.qwen3_8b_local`. A missing or wrong GGUF path is the usual cause; confirm the file exists where the plan's `launch:` line says.

To require a key even locally, add `api_key = secret("LOCAL_API_KEY")` to the deployment and export `LOCAL_API_KEY` before `apply`, then send `Authorization: Bearer $LOCAL_API_KEY`.

## Path B: on a GPU provider

The steps are the same for any provider:

1. Pick a provider from the [registry](/docs/providers) and create an account there.
2. Export its credentials in your shell. Never write them into HCL.
3. Set `provider` (and optionally `region`) on the `hardware_profile`.
4. Give the deployment an endpoint key: `api_key = secret("CHAT_API_KEY")`, with `CHAT_API_KEY` exported. Every off-machine endpoint needs one.
5. Run `amicu validate`, `amicu plan`, `amicu apply`.

`plan` shows `api_key: ******` and never reads the key. `apply` starts the deployment and then checks that the endpoint rejects anonymous requests and accepts your key. The first deploy downloads the weights and can take several minutes.

Today, `apply` supports Modal as a remote GPU provider. Hetzner, OVHcloud, Scaleway, RunPod and SSH are in preview (adapter built, not wired into `apply`), and AWS, Azure, GCP and Nebius are planned. Selecting one of those fails at `apply` with a clear error before anything starts. Each provider page has its own setup and troubleshooting.

`validate` and `plan` print the warning `AMICU-CAP-010` for this model, because it does not declare `n_layers`, `n_kv_heads`, and `head_dim`. It is expected: the fit check then covers weights only. Declare the shape on the model to silence it.

## 4. Tear down

There is no `destroy` command. Amicu removes what is no longer declared: delete the `deployment` resource from your HCL and run `amicu apply`. The plan shows a `destroy` action and apply stops the service.

Some providers also have a direct stop command; see the provider page (for example [Modal](/docs/providers/modal#monitoring)).
